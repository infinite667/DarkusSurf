# Security policy

## Supported versions

v0.4.0 is a development preview, not a security-audited or production-supported release. Security fixes are handled on a best-effort basis. Do not use it for high-risk anonymity needs.

## Reporting a vulnerability

Prefer GitHub's private vulnerability reporting feature if the maintainer has enabled it (Security > Report a vulnerability). If unavailable, open a minimal public issue asking for a private reporting channel, without exploit details, credentials, IP addresses, bridge lines or private logs. Do not test against devices or services without authorization. Include version, OS, minimal reproduction steps and redacted diagnostic information in the private report. No response-time guarantee is offered.

Report suspected malicious distribution, tampering or unexpected network behavior; do not bypass antivirus warnings. Verify the release checksum and upstream signatures independently. Checksums are integrity checks, not publisher authentication. Current historical preview binaries are unsigned and their original embedded bundle was not independently authenticated.
